# task023-gitignore

gitignore 风格的忽略规则匹配引擎，仅使用标准库实现：接收一段多行 .gitignore 风格规则文本与一组相对路径，按「最后命中决定」语义判定每个路径是否被忽略，并返回决定该结果的规则原文、行号与是否取反。所有判定只依据规则文本，不持久化、不依赖任何第三方库、数据库或外部服务。

## 本地运行

```bash
go run . server --addr :8080
go run . --smoke-test
```

主要接口（请求体均为单个 JSON 对象，未知字段与多段 JSON 会被拒绝）：

- `GET /healthz`：健康检查。
- `POST /check`：提交 `{"rules":"<规则文本>","paths":["a/b",...]}`，返回 `{"results":[{"path","ignored","rule","line","negated"}],"ignored":[...],"kept":[...]}`。每个路径的 `ignored` 由「最后一条命中规则」决定：普通规则命中→忽略，取反规则(`!` 前缀)命中→保留，无命中→保留。空规则文本→所有路径保留；空路径列表→空结果；空路径字符串或纯 `/` 路径→400。

匹配语义要点：

- 通配符：`*` 不跨 `/`，`?` 匹配单个非 `/` 字符，`**` 匹配任意层级（含零层）目录段。
- 锚定：规则以 `/` 开头或含分隔符 `/`（除行尾 `/`）时锚定到根；否则按基名匹配任意层级。
- 目录规则：以 `/` 结尾只匹配目录，命中某段为目录时其下全部路径被忽略；同名叶子文件不被目录规则忽略。
- 转义：`\#`、`\!`、`\ `、`\*` 等表示字面字符，不作注释/取反/通配符。
- 注释：空行与未转义 `#` 开头的行不参与匹配。

边界约束要点：

- 最后命中决定与取反重新包含：忽略/保留由最后一条命中规则决定；`!` 取反规则可把先前被忽略的路径重新包含。
- `*` 不跨分隔符、`**` 跨任意层级：`a/*.txt` 命中 `a/notes.txt` 但不命中 `a/sub/notes.txt`；`a/**/b` 同时命中 `a/b` 与 `a/x/y/b`。
- 锚定与基名差异：`/foo` 命中 `foo` 但不命中 `bar/foo`；`foo` 同时命中 `foo`、`a/foo`、`a/foo/b`。
- 目录规则递归忽略与专属性：`build/` 忽略 `build/out.o` 与 `build`，但不忽略 `src/build`（叶子文件）。

## Docker

镜像使用国内 DaoCloud Go 1.26.3 Bookworm builder 和 Alpine 3.20 runtime；支持 `linux/amd64` 与 `linux/arm64` 双架构。
